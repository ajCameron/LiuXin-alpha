# Native cache typing pass — 2026-11-18

The entire `src/LiuXin_alpha/caches` package is now in both configured type
checker scopes. Previously only `custom_fields.py` and `field_metadata.py` were
explicit cache targets. The first whole-package check exposed 189 basedpyright
errors and 227 mypy errors; an earlier green repository check did not establish
whole-cache typing coverage.

## Contracts

- Storage registries expose read-only mapping contracts; concrete backends keep
  their existing dictionaries behind properties. Main-table contracts include
  row IDs, membership, ID columns and detached row snapshots. Field contracts
  expose canonical field keys.
- Database handles are typed throughout backend creation, reads, refreshes and
  mutation helpers. Borrowed attachments are nullable after detach. SQL-dependent
  table operations require an attachment; loaded snapshot reads remain available.
- Cardinality getter declarations match concrete argument ordering and return
  ordinary `RowAPI` values. They no longer promise specialized interlink rows.
  Relation mixins share the field API base and declare the endpoint/table state
  that their implementations use.
- `QueryStorage`, `QueryTable`, `QueryField`, `QueryLink` and `PredicateReadEngine`
  describe the read surface shared by storage and projections. Projection fields
  are typed values; the projection no longer masquerades as storage via `Any`.
  Query memoization preserves key/value types, and predicate nodes use the native
  predicate union.
- The writable Catalog bridge lives in `cache.py`. Bound typed operations replace
  method-name dispatch for prepared updates. The bridge satisfies
  `CatalogWriterHostAPI` directly. `Cache.create_writer` exposes the concrete
  writer union; the abstract facade exposes `CacheWriter`. Receipts retain integer
  row keys and a read-only mapping shape. `read_cache.py` remains independent of
  Catalog imports.
- NumPy availability is an explicitly optional module handle. Plugin loaders and
  factories expose storage class/instance types. A namespace package without a
  file now raises a descriptive `CachePluginError` when its location is requested.

## Deliberately dynamic boundaries

This is whole-package checking, not a promise that every value has a closed
static type. Mypy retains the repository's strict configuration (including its
existing `warn_return_any = false`); basedpyright retains standard mode. No new
blanket suppressions, exclusions or relaxed checker settings were added.

SQL cells and plugin-defined field payloads can be scalars, collections or richer
objects, so their values remain `Any`. A schema-selected writer also accepts
payloads whose shape depends on the selected writer. Optional NumPy buffers remain
dynamic because the same helpers support arrays and tuple fallbacks. Dynamic plugin/proxy hooks
and legacy row payloads are narrowed at their boundaries. The Catalog constructor
also has a localized `DatabaseHandle` cast: its read protocol requires a metadata
SQL handle, whereas `DatabaseAPI` allows that handle to be absent. The prepared
writer path uses the native driver/schema capabilities; this pass does not change
Catalog's wider read-handle contract. Static checking cannot
prove that an arbitrary imported plugin implements its advertised contract; runtime
backend conformance tests remain necessary.

The core exception adapter also needed its optional cache-error import rewritten
as `try/except/else`: assigning an empty tuple to the imported exception class
became an error once the cache exports were statically visible. Classification
and receipt behavior are unchanged.
